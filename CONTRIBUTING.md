# Contributing · 参与贡献

*English first; 中文在后。*

## English

Thanks for wanting to help. Issues and pull requests are answered in English and Chinese alike — write in whichever you prefer.

### Reporting a problem or asking for a feature

- **Bugs**: open an [issue](https://github.com/moonbai-studio/tungsten-edge/issues/new/choose) with the bug report form. Fill in both version fields (Tungsten Edge and macOS) — without them we usually have to ask again before we can look.
- **Concrete feature requests** also go to [Issues](https://github.com/moonbai-studio/tungsten-edge/issues).
- **Questions, installation help, ideas you want to talk through**: use [Discussions](https://github.com/moonbai-studio/tungsten-edge/discussions).
- Search existing issues first; if yours is already there, add what you see to it instead of opening a new one.

### Pull requests

- **Talk first.** Before writing anything bigger than a small fix, describe the idea in an issue or in Discussions. Tungsten Edge has many deliberate behaviours that look like bugs from the outside, and agreeing on the approach first saves you from a PR that cannot be merged.
- **Agree to the CLA.** We merge a pull request only after the Contributor License Agreement below has been agreed to for all the work in it — by each author, or by someone authorised to agree on that author's behalf. The pull request template has a checkbox with this sentence — read the agreement, then tick it:

  > I have read the Contributor License Agreement (version 1.0) in CONTRIBUTING.md and I agree to it for this and all my future contributions to this repository.

  Any other author whom you are not authorised to represent posts the same sentence as a comment on the pull request. Third-party code kept under its own license is the one exception; list it as point 5 of the agreement says. A pull request without it will not be reviewed until it is added.
- **Contributing for someone else.** If your employer or anyone else holds rights in the work, say so in the pull request; you must be authorised to grant every right in the agreement on their behalf.
- **Code posted in issues or Discussions** is treated as a hint only. We use it directly only after its author has agreed to the CLA — in that thread, or by turning it into a pull request.

## 中文

谢谢你愿意帮忙。Issue 和 Pull Request 中文英文都会回复，用哪种都可以。

### 报告问题、提功能请求

- **Bug**：用报告表单开一个 [issue](https://github.com/moonbai-studio/tungsten-edge/issues/new/choose)，两栏版本号（钨极和 macOS）都要填——缺了的话，我们通常得先回头再问一次才能看。
- **明确的功能请求**也提到 [Issues](https://github.com/moonbai-studio/tungsten-edge/issues)。
- **用法问题、安装求助、想先聊聊的点子**：请到 [Discussions](https://github.com/moonbai-studio/tungsten-edge/discussions)。
- 先搜一下已有的 issue；已经有人提过的，在那条下面补充你的情况，不用另开。

### Pull Request

- **先沟通。** 比小修补大的改动，动手之前先在 issue 或 Discussions 里讲讲思路。钨极有很多从外面看像 bug、其实是有意为之的行为，先对好做法，免得写完的 PR 合不进来。
- **同意 CLA。** PR 里的全部作品都已就下方的贡献者许可协议取得同意——由每位作者本人，或由获授权代该作者同意的人——之后才能合并。PR 模板里有一个带这句话的勾选框，读完协议再勾上：

  > I have read the Contributor License Agreement (version 1.0) in CONTRIBUTING.md and I agree to it for this and all my future contributions to this repository.

  （意思是：「我已阅读 CONTRIBUTING.md 中的贡献者许可协议（1.0 版），并就本次及今后对本仓库的全部贡献同意该协议。」这句请保留英文原文。）你没获授权代表的其他作者，在 PR 下用评论发同一句话。唯一的例外是仍按其原许可证使用的第三方代码，照协议第 5 条在 PR 里列明即可。没有这句的 PR，补上之前不会进入审查。
- **代别人贡献。** 如果你的雇主或其他人对这份作品享有权利，请在 PR 里说明；你必须已获授权，能代他们授予协议里的全部权利。
- **贴在 issue 或 Discussions 里的代码**只当线索。作者在那条讨论里同意 CLA、或把它改成 PR 之后，我们才会直接采用。
